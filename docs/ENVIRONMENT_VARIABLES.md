# Environment variables

Every setting the app reads comes from an environment variable or, locally,
from a `.env` file beside the code (`cp env.example .env` is a starting
point). Names are not case-sensitive. The bot and the web process read the
same settings (`vechnost_bot/config.py`, class `Settings`).

Which ones production has to set, and why, is in
[`RAILWAY_DEPLOYMENT.md`](RAILWAY_DEPLOYMENT.md#variables). With
`ENVIRONMENT=production` the app refuses to start on a development default
and names every variable to fix, without printing any value.

## Settings

The table is generated from `Settings` by `scripts/env_docs.py`, and
`tests/test_env_docs.py` fails when it no longer matches: after adding,
renaming or re-describing a setting, run `python scripts/env_docs.py --write`
and commit the result. The descriptions are the fields' own.

| `ENVIRONMENT` | `development` | Application environment. `production` makes the service refuse to start on development defaults (see production_problems), and tags Sentry events. |
| `REDIS_URL` | unset | Redis for bot sessions. Unset: sessions stay in the bot process's memory. |
| `REDIS_DB` | `0` | Redis database number, when REDIS_URL names none |
| `CHAT_ID` | unset | Optional chat ID for notifications |
| `SENTRY_DSN` | unset | Sentry DSN for error tracking |
| `MAX_CONNECTIONS` | `20` | Maximum Redis connections |
| `SESSION_TTL` | `3600` | Seconds a bot session outlives its last save, in memory and in Redis alike |
| `ENABLE_PAYMENT` | `false` | Enable payment requirement |
| `TRIBUTE_API_KEY` | unset | Tribute API key for authentication |
| `TRIBUTE_BASE_URL` | `https://api.tribute.to` | Tribute API base URL |
| `TRIBUTE_PAYMENT_URL` | `https://tribute.to/vechnost` | Tribute payment page URL for users |
| `WEBHOOK_SECRET` | unset | Optional second key webhooks may be signed with, for a relay or a test harness in front of the endpoint. Tribute itself signs with TRIBUTE_API_KEY; this is accepted alongside it, never instead of it. |
| `ADMIN_IDS` | unset | Comma-separated Telegram user ids allowed to run the bot's admin commands (/broadcast). Unset means nobody is: the commands are not registered at all, which is the safe default for a bot that can message everyone. |
| `ADMIN_TOKEN` | unset | Bearer token for the /admin endpoints. Falls back to TRIBUTE_API_KEY so existing deployments keep working, but set it: TRIBUTE_API_KEY is an outbound credential and reusing it as an inbound password means one leak costs both. |
| `DATABASE_URL` | `sqlite:///./vechnost.db` | Database connection URL |
| `WEBAPP_URL` | unset | HTTPS URL of the Telegram Mini App (e.g. https://\<railway-app>/app). When set, the bot shows a 'Play in app' button. |
| `BOT_USERNAME` | `tvoya_vechnost_bot` | Bot username without @, used for the brand watermark on shared card images and share links. |
| `WEBAPP_SHORT_NAME` | unset | The short name of a *named* Mini App, made in BotFather with /newapp. With it, an invite is a direct link (t.me/\<bot>/\<short name>?startapp=...) that opens the app on the right screen in one tap. |
| `WEBAPP_MAIN_APP` | `false` | Set when the bot has a Main Mini App (BotFather -> Bot Settings -> Configure Mini App). Its direct link carries no short name at all — t.me/\<bot>?startapp=... — which is why this is its own switch rather than a value in WEBAPP_SHORT_NAME. One tap, same as a named app; the short name wins if somehow both are configured. With neither, invites fall back to t.me/\<bot>?start=..., where the bot answers with a button into the app. |
| `ACCESS_PRODUCT_ID` | unset | Tribute product id of the access itself. The Mini App's buy button, the price it shows and the bot's purchase button use exactly this product. Unset, they use the cheapest synced product that is neither the gift (GIFT_PRODUCT_ID) nor the referral discount (REFERRAL_PAYMENT_URL). |
| `GIFT_PRODUCT_ID` | unset | Tribute product id for the gift certificate. Payments for this product produce a certificate instead of buyer access. |
| `GIFT_PAYMENT_URL` | unset | Tribute payment page for the gift certificate product. The gift button is hidden when neither this nor a synced gift product link is available. |
| `CORS_ALLOW_ORIGINS` | unset | Comma-separated origins allowed to read API responses from script. The Mini App is same-origin and needs none, so the default is no allowance at all. |
| `TRUSTED_PROXY_HOPS` | `1`, 1–5 | How many proxies stand between the internet and this app and append to X-Forwarded-For. The rate limiter reads the client address that many entries from the end of the header; the entries before it were written by the client. One on Railway; two with a CDN in front. |
| `ALLOWED_HOSTS` | unset | Comma-separated hostnames this deployment answers to. Set it in production: unset, a forged Host header is accepted. |
| `REFERRAL_PAYMENT_URL` | unset | Tribute page for the discounted product shown to users who arrived through someone's referral link. Unset means referrals are still tracked but everyone pays full price. |
| `REFERRAL_DISCOUNT_PERCENT` | `10`, 1–90 | What the referral page is worth, for the copy only. The price itself lives in the Tribute product. |
| `DAILY_CARD_ENABLED` | `true` | Send the daily card push to registered users. |
| `DAILY_CARD_HOUR_UTC` | `17`, 0–23 | UTC hour when the daily card is sent (17 = ~19:00 Prague). |

## Read outside Settings

| Variable | Read by | What it does |
|---|---|---|
| `PORT` | `run_webhook.py` | The port the web process listens on; Railway sets it. Default `8000`. |
| `RAILWAY_GIT_COMMIT_SHA` | `payments/web.py`, `monitoring.py` | The deployed commit: `/health` reports it and Sentry files events under it. Railway sets it. |
| `RELEASE_VERSION` | `monitoring.py` | Sentry's release when `RAILWAY_GIT_COMMIT_SHA` is unset. |

## Tests and CI only

| Variable | What it does |
|---|---|
| `POSTGRES_TEST_URL` | Runs `tests/test_postgres.py` against that PostgreSQL server. |
| `E2E_DATABASE_URL` | Points the in-process two-user suite at another database, e.g. PostgreSQL. |
| `E2E_BASE_URL` | Sends the two-user suite over real HTTP to a live server (and runs the race tests). |
| `E2E_BOT_TOKEN` | The token a live server signs initData with, when it is not `TELEGRAM_BOT_TOKEN`. |
| `E2E_FUZZ_EXAMPLES`, `E2E_FUZZ_STEPS` | The fuzzer's budget. |
| `E2E_BROWSER` | `1` runs the two Chromium phones in `tests/e2e/browser`. |
| `E2E_REPORT_DIR` | Where screenshots, traces and the fuzzer's coverage go (default `./e2e-report`). |

The test suite needs none of the settings above: `tests/conftest.py` supplies
a fake `TELEGRAM_BOT_TOKEN` and overrides `DATABASE_URL` with a throwaway
SQLite file. The GitHub repository variables `PRODUCTION_URL` and
`PRODUCTION_ENVIRONMENT` belong to the production smoke and are described in
[`CI_CD.md`](CI_CD.md).
