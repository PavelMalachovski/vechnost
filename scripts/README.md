# Scripts

Вспомогательные скрипты. Каждый берёт `DATABASE_URL` и остальные настройки
из переменных окружения (или `.env`) через настройки самого приложения; ни
один не содержит учётных данных, и в примерах ниже только выдуманные
Telegram id. У каждого есть `--help`, и `tests/test_scripts.py` запускает его
у всех на каждом прогоне: скрипт, который перестал импортироваться или
начинает работать раньше, чем прочитал аргументы, роняет сьют.

## Администрирование

- **`check_user_simple.py`** – показать, что база знает о пользователе:
  строку, подписки (пожизненные тоже), платежи и есть ли доступ. Читает через
  репозитории приложения, поэтому одинаково работает на SQLite и PostgreSQL.
- **`broadcast.py`** – рассылка всем пользователям; без `--confirm` ничего не
  отправляет (см. корневой README, раздел «Broadcasts»).
- **`generate_certificates.py`** – выпустить подарочные сертификаты и QR-коды.
  Коды минтит та же `payments/gifts.py`, что и купленные подарки, а QR-карточки
  ложатся в `certificates/` (в `.gitignore`); другую папку внутри репозитория
  скрипт не примет, пока git её не игнорирует. Коды печатаются в консоль и
  больше нигде не сохраняются: не вставляйте их в документацию,
  `tests/test_no_secrets.py` это отловит. `--sql` дополнительно пишет
  `certificates.sql`, чтобы загрузить те же коды в продовую базу, если
  печатали не на ней.
- **`sync_products.py`** – подтянуть продукты из Tribute API (то же, что
  `POST /admin/sync-products`).

Выдать доступ вручную – значит выпустить один сертификат
(`python scripts/generate_certificates.py 1`) и отправить код человеку: он
активирует его командой `/activate` в боте. Скрипта, который пишет подписку
сырым SQL, больше нет: он не видел пожизненные подписки и обходил правила
репозиториев.

## Контент и ассеты

- **`generate_card_assets.py`** – детерминированная генерация карточных
  фонов и мастей (см. CLAUDE.md).
- **`fetch_webapp_fonts.py`** – собрать woff2-шрифты Mini App: по одному
  файлу на начертание из двух подмножеств Google, только то, что приложение
  набирает (кириллица, ASCII, типографская пунктуация). Нужен fontTools из
  extra `dev`.

## Разработка и деплой

- **`test_webhook.py`** – отправить подписанный вебхук Tribute на локальный
  сервер (`--url`, чтобы на другой).
- **`smoke_production.py`** – read-only проверка развёрнутого web-процесса
  (см. `docs/CI_CD.md`).
- **`typecheck.sh`** – mypy на списке модулей, которые обязаны быть
  типизированы (гейт CI).

Локальный веб-сервер запускается одной командой из корневого README:
`python -m uvicorn vechnost_bot.payments.web:app --reload --port 8000`.

## Примеры

```bash
python scripts/check_user_simple.py 123456789
python scripts/generate_certificates.py 1
python scripts/broadcast.py --message-file msg.txt --dry-run
python scripts/test_webhook.py
```

## Заметки

1. Скрипты администрирования меняют продовую базу. Проверьте `DATABASE_URL`
   перед запуском.
2. Против Railway удобнее всего запускать через `railway shell`.
3. Ничего из этой папки не должно содержать реальных id, паролей и кодов:
   `pytest tests/test_no_secrets.py` проверяет это на каждом прогоне.
